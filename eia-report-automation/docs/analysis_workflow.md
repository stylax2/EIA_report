# 분석 워크플로

한글 문서를 다루기 전 단계의 설계다. 원자료에서 분석 결과까지를 확정하고,
그 결과를 **웹페이지로 먼저 검증한 뒤** HWPX 조판으로 넘긴다.

```
Excel 3종 → 정규화·조인 → 검증 → 분석(T1/T2/T3) → 결과 객체
                                                    ├→ 웹페이지 (지금 단계)
                                                    ├→ 그래프
                                                    └→ HWPX (다음 단계)
```

웹페이지를 먼저 두는 이유는, 수치가 맞는지 사람이 확인하는 비용이 한글
문서보다 훨씬 싸기 때문이다. 조판 단계에서 수치 오류를 발견하면 되돌리는
비용이 크다.

## 1. 원자료 3종의 역할

| 파일 | 역할 | 비고 |
|---|---|---|
| `EIA_표준종목록_마스터DB_통합본_v6.xlsx` | 종의 속성 원천 | 분류체계, 법정 지위, 분류군별 속성 |
| `EIA_표준종목록_입력용_데이터시트_v6.xlsx` | 사용자 배포용 빈 입력지 | 5개 컬럼만 노출 |
| `EIA_가상데이터.xlsx` | 파일럿 테스트용 입력 완료본 | 입력지 + 출현 4개 컬럼 |

세 파일의 분류군 시트와 행 순서·행 수가 모두 일치한다(확인 완료). 입력지는

컬럼을 붙인 것이다.

## 2. 조인 전략

### 문제
입력지와 가상데이터에 **`species_id` 가 없다.** 마스터DB의 속성을 붙이려면
조인 키가 필요한데, 국명과 학명은 유일하지 않다.

| 분류군 | 국명 중복 | 학명 중복 |
|---|---|---|
| 조류 | 21 | 0 |
| 어류 | 1 | 0 |
| 육상곤충류 | 1,051 | 0 |
| 저서성대형무척추동물 | 6 | 0 |
| 관속식물 | 444 | 425 |

관속식물은 학명까지 중복된다(예: `FL00430` / `FL00431` 이 모두
*Abies nephrolepis* 분비나무). 이명 관계인 경우(*Acer ginnala* → 광이신나무 /
붉신나무)와 단순 중복이 섞여 있다.

### 채택안
1. **행 위치로 조인한다.** 세 파일의 행 순서가 동일하므로 인덱스 조인이
   가장 정확하다.
2. **조인 직후 국명·학명 일치를 검증한다.** 한 행이라도 어긋나면 오류로
   중단한다. 사용자가 행을 정렬하거나 삽입했을 때를 잡기 위해서다.
3. **향후 입력지에 `species_id` 를 추가한다.** 숨김 컬럼이라도 넣어두면
   위치 의존을 없앨 수 있다. → 개선 과제

### 학명 표기 정규화
마스터DB와 입력지의 학명은 유니코드 수학 이탤릭
(`𝐸𝑟𝑖𝑛𝑎𝑐𝑒𝑢𝑠 𝑎𝑚𝑢𝑟𝑒𝑛𝑠𝑖𝑠`)이고 가상데이터는 ASCII(`Erinaceus amurensis`)다.
엑셀에서 이탤릭 서식 대신 문자 자체를 바꾼 결과다. 비교·출력 전에 NFKC
정규화로 ASCII 화한다. 한글 문서에서는 실제 이탤릭 서식으로 조판한다.

## 3. 출현값 해석

컬럼 값의 의미가 분류군마다 다르므로, 값을 그대로 쓰지 않고 세 가지로
파싱한다.

| 파싱 결과 | 의미 |
|---|---|
| `present` | 출현 여부(bool) — 모든 분류군 |
| `individuals` | 개체수(int 또는 NA) — 조류·어류·저서무척추만 |
| `methods` | 조사방법 코드 목록 — 포유류만 |

### 값 규칙
- 빈칸 → 미출현
- `1` → 출현 (개체수 아님)
- 정수 → 출현, 개체수 = 그 값 (조류·어류·저서무척추)
- `SI` `TR` `SC` `AU` `CT` 및 `/` 결합 → 출현, 조사방법 (포유류)

포유류의 `1` 과 조류의 `1` 은 다르다. 전자는 단순 출현 표시이고 후자는
개체수 1개체다. **분류군별 파서를 분리해야 하는 이유가 여기에 있다.**

### 포유류 조사방법 코드
| 코드 | 의미 |
|---|---|
| SI | 목견 |
| TR | 족적 |
| SC | 배설물 |
| AU | 청문 |
| CT | 카메라트랩 |

## 4. 검증 단계

분석 전에 다음을 확인하고, 오류는 중단·경고는 기록 후 진행한다.

| 검사 | 수준 |
|---|---|
| 시트 존재 및 필수 컬럼 | 오류 |
| 행 수·행 순서가 마스터DB와 일치 | 오류 |
| 국명·학명 대조 | 오류 |
| 분류군에 허용되지 않는 값 유형 (예: 관속식물에 개체수) | 경고 |
| 알 수 없는 조사방법 코드 | 경고 |
| 개체수 0 또는 음수 | 경고 |
| 마스터DB 중복 행 (관속식물) | 경고 |

## 5. 분석 실행

분석항목은 `analysis_items.md` 의 T1 / T2 / T3 카탈로그를 따른다. 실행
순서는 다음과 같다.

1. **T1 공통** — 8개 분류군 전부 실행
2. **T2 분류군 특이** — 해당 분류군에만 실행
3. **T3 정량** — 개체수가 파싱된 분류군에만 실행. 없으면 `자료 없음` 사유를
   결과에 남긴다.

결과는 분류군당 하나의 `TaxonResult` 객체로 모은다. 이 객체가 웹페이지,
그래프, HWPX 조판의 **공통 입력**이 된다. 산출물마다 따로 계산하지 않는다.

```
TaxonResult
├── taxon               분류군
├── totals              T1-01~03 종수
├── taxonomy            T1-04 분류체계 구성
├── legal               T1-05~07 법정보호종
├── species_rows        T1-08 종목록
├── specific            T2 분류군 특이 결과
├── quantitative        T3 정량 결과 (없으면 None + 사유)
└── notes               경고·가정 기록
```

---

## 6. 웹페이지 표출

`TaxonResult` 를 정적 HTML 한 장으로 렌더링한다. 외부 자원을 참조하지 않아
브라우저만 있으면 열린다.

### 구성
- 분류군 탭 8개
- 상단 요약 카드: 총 출현종수 / 문헌·현지 / 법정보호종 / 교란종
- 조사구분·차수별 종수 표
- 과별 종수 상위 막대
- 법정보호종·교란종 목록
- T2 분류군 특이 결과
- T3 군집지수 (없으면 사유 표시)
- 종목록 표 (검색·필터)

### 원칙
- 화면에 뜨는 모든 수치는 `TaxonResult` 에서 온다. 렌더링 단계에서 다시
  계산하지 않는다.
- 산출 불가 항목은 빈칸이 아니라 **사유 문구**로 표시한다.
- 이 페이지의 수치가 확정되면 그대로 HWPX 로 넘긴다.

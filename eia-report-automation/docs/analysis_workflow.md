# 분석 워크플로

한글 문서를 다루기 전 단계의 설계다. 원자료에서 분석 결과까지를 확정하고,
그 결과를 **웹페이지로 먼저 검증한 뒤** HWPX 조판으로 넘긴다.

```
Excel 3종 → 정규화·조인 → 검증 → 분석(T1/T2/T3) → 결과 객체
                                                    ├→ 웹페이지 (지금 단계)
                                                    ├→ 그래프
                                                    └→ HWPX (다음 단계)
```

웹페이지를 먼저 두는 이유는, 수치가 맞는지 사람이 확인하는 비용이 한글
문서보다 훨씬 싸기 때문이다. 조판 단계에서 수치 오류를 발견하면 되돌리는
비용이 크다.

## 1. 원자료 3종의 역할

| 파일 | 역할 | 비고 |
|---|---|---|
| `EIA_표준종목록_마스터DB_통합본_v7.xlsx` | 종의 속성 원천 | 분류체계, 법정 지위, 분류군별 속성, 정비이력 |
| `EIA_표준종목록_입력용_데이터시트_v8.xlsx` | 사용자 배포용 빈 입력지 | 조인 키 + 표시용 5개 컬럼 |
| `EIA_가상데이터_v8.xlsx` | 파일럿 테스트용 입력 완료본 | 입력지 + 출현 컬럼(정점 포함) |

마스터DB는 v8 에서 바뀌지 않아 v7 을 그대로 쓴다. 정점 컬럼은 조사자료
쪽에만 생기기 때문이다.

입력지는 마스터DB에서 표시용 컬럼만 뽑아낸 뷰이고, 예시데이터는 거기에
출현 컬럼을 붙인 것이다. 세 파일은 `species_id` 로 연결된다.

v6 파일은 대조용으로 남겨 둔다. v7 은 `tools/repair_datamaster.py` 로
생성하며, 무엇을 왜 바꿨는지는 마스터DB의 `정비이력` 시트에 있다.

### 정점조사 (v8)

어류와 저서성대형무척추동물은 **정점조사**를 한다. v7 까지는 현지조사가
회차당 컬럼 하나여서 지점별 분석이 통째로 막혀 있었다. v8 에서 회차를
정점 5개로 펼쳤다.

```
현지조사1  →  현지조사1_St1 … 현지조사1_St5
현지조사2  →  현지조사2_St1 … 현지조사2_St5
```

문헌조사는 정점 개념이 없으므로 그대로 둔다. 나머지 6개 분류군도 컬럼
구조가 바뀌지 않는다. 정점 데이터는 `tools/make_station_sample.py` 가
시드를 고정해 생성하므로 언제 돌려도 같은 결과가 나온다.

컬럼 목록은 상수가 아니라 `schema.survey_columns(spec)` 가 분류군별로
만들어 준다. 분석 계층은 `columns_in(df)` 로 자료에 실제로 실린 컬럼을
읽으므로 정점 유무와 무관하게 동작한다.

### 입력 컬럼

| 컬럼 | 내용 |
|---|---|
| `species_id` | 마스터DB 조인 키. 수정·삭제·정렬 금지 |
| `family_kr` | 과명(국문) |
| `scientific_name` | 학명 |
| `korean_name` | 국명 |
| `abb` | 법정 지위 통합 약어 (멸Ⅰ/멸Ⅱ/천/교, 식물은 구계등급·희귀등급·특/귀 추가) |
| `abb2` | 시·도보호종 통합 |
| `문헌1` `문헌2` | 문헌조사 1·2차 |
| `현지조사1` `현지조사2` | 현지조사 1·2차 |

## 2. 조인 전략

### v6 의 문제
입력지와 가상데이터에 **`species_id` 가 없었다.** 마스터DB의 속성을 붙이려면
조인 키가 필요한데 국명·학명은 유일하지 않았다. 관속식물은 학명까지
중복됐다(`FL00430` / `FL00431` 이 모두 *Abies nephrolepis* 분비나무).

행 위치로 조인할 수밖에 없었고, 사용자가 행을 정렬·삽입하면 조용히 깨졌다.

### v7 의 해법
입력지와 예시데이터의 **첫 컬럼에 `species_id` 를 넣었다.** 정비 절차는
`tools/repair_datamaster.py` 에 있다.

```
species_id | family_kr | scientific_name | korean_name | abb | abb2 | 문헌1 …
```

`load_taxon()` 은 조사자료에 `species_id` 가 있으면 그것으로 조인하고,
없으면(v6 이하) 행 위치로 조인한 뒤 경고를 남긴다.

| 상황 | v6 (위치 조인) | v7 (키 조인) |
|---|---|---|
| 행 정렬 | 조용히 깨짐 → 국명 대조로 검출 | 영향 없음 |
| 행 삭제 | 오류 중단 | 미출현으로 처리 + 경고 |
| 행 추가 | 오류 중단 | 오류 중단(마스터DB 미등록) |
| id 중복 | — | 오류 중단 |

### 학명 표기
v6 은 마스터DB·입력지가 유니코드 수학 이탤릭(`𝐸𝑟𝑖𝑛𝑎𝑐𝑒𝑢𝑠 𝑎𝑚𝑢𝑟𝑒𝑛𝑠𝑖𝑠`),
가상데이터가 ASCII 로 서로 달랐다. v7 에서 **ASCII 로 통일**하고 이탤릭은
셀 서식으로 준다. 이탤릭은 데이터가 아니라 표현이기 때문이다. 유니코드
이탤릭은 정렬·검색·VLOOKUP 을 모두 깨뜨린다.

잡종 기호 `×`(U+00D7)는 식물 명명법상 정상이므로 유지한다.

## 3. 출현값 해석

컬럼 값의 의미가 분류군마다 다르므로, 값을 그대로 쓰지 않고 세 가지로
파싱한다.

| 파싱 결과 | 의미 |
|---|---|
| `present` | 출현 여부(bool) — 모든 분류군 |
| `individuals` | 개체수(int 또는 NA) — 조류·어류·저서무척추만 |
| `methods` | 조사방법 코드 목록 — 포유류만 |

### 값 규칙
- 빈칸 → 미출현
- `1` → 출현 (개체수 아님)
- 정수 → 출현, 개체수 = 그 값 (조류·어류·저서무척추)
- `SI` `TR` `SC` `AU` `CT` 및 `/` 결합 → 출현, 조사방법 (포유류)

포유류의 `1` 과 조류의 `1` 은 다르다. 전자는 단순 출현 표시이고 후자는
개체수 1개체다. **분류군별 파서를 분리해야 하는 이유가 여기에 있다.**

### 포유류 조사방법 코드
| 코드 | 의미 |
|---|---|
| SI | 목견 |
| TR | 족적 |
| SC | 배설물 |
| AU | 청문 |
| CT | 카메라트랩 |

## 3.5 v6 → v7 정비 내역

`python -m tools.repair_datamaster` 로 재현한다. 전체 1,195건이 마스터DB의
`정비이력` 시트에 남는다.

| 구분 | 건수 | 내용 |
|---|---|---|
| 계급 보정 | 680 | 연결어 없는 3단어 학명을 종 → 아종 (*Anax parthenope julius* 등) |
| 중복 병합 | 370 | 학명·국명이 같은 행을 하나로 합침 |
| 병합 충돌 | 86 | 병합 시 값이 달라 첫 값 채택. 버린 값을 기록 |
| 분류체계 보정 | 21 | 같은 속의 다른 행에서 문·강·목·과를 채움 |
| abb 재계산 | 14 | 병합 후 구성요소로 다시 생성 |
| 학명 표기 | 8 | EN DASH → 하이픈 7건, 속명 대문자 1건 |
| 국명 표기 통일 | 2 | `국명없음`·`국명미정` → `[국명없음]` 1,059건 |
| 분류체계 미보정 | 3 | 같은 속의 참조 행이 없어 비워 둠 |
| 확인 필요 | 3 | 국명 결측 — 지어내지 않고 남김 |

### 하지 않은 것

- **국명을 지어내지 않았다.** 국명 없는 종 1,061건(육상곤충류 1,051 ·
  관속식물 8 · 어류 2)은 `[국명없음]` 으로 통일만 하고 그대로 뒀다. 표기
  통일 덕분에 "국명 중복"으로 잘못 집계되던 문제는 사라졌다.
- **이명을 통합하지 않았다.** 학명은 같고 국명이 다른 18그룹
  (*Acer ginnala* → 광이신나무 / 붉신나무)은 분류학적 판단이 필요하므로
  건드리지 않았다.
- **잡종 계급을 고치지 않았다.** `×` 가 붙은 82건 중 계급이 종·잡종으로
  섞여 있으나 판단 근거가 없어 그대로 뒀다.

병합으로 사라진 행의 출현 기록은 남는 행으로 옮겼다. 개체수는 합산하고
조사방법 코드는 결합한다. 정비 전후로 개체수 합계가 바뀌지 않는 것을
확인했다(조류 8,936 · 어류 4,320 · 저서무척추 31,011).

## 5. 분석 실행

분석항목은 `analysis_items.md` 의 T1 / T2 / T3 카탈로그를 따른다. 실행
순서는 다음과 같다.

1. **T1 공통** — 8개 분류군 전부 실행
2. **T2 분류군 특이** — 해당 분류군에만 실행
3. **T3 정량** — 개체수가 파싱된 분류군에만 실행. 없으면 `자료 없음` 사유를
   결과에 남긴다.

결과는 분류군당 하나의 `TaxonResult` 객체로 모은다. 이 객체가 웹페이지,
그래프, HWPX 조판의 **공통 입력**이 된다. 산출물마다 따로 계산하지 않는다.

```
TaxonResult
├── taxon               분류군
├── totals              T1-01~03 종수
├── taxonomy            T1-04 분류체계 구성
├── legal               T1-05~07 법정보호종
├── species_rows        T1-08 종목록
├── specific            T2 분류군 특이 결과
├── quantitative        T3 정량 결과 (없으면 None + 사유)
└── notes               경고·가정 기록
```

## 5.5 분석 단위(Scope)

분석가는 "이 분류군의 이 회차·정점에서 무엇이 나오는가"를 보고 평가서에
넣을 표·그래프를 고른다. 그 선택 단위를 `src/analysis/scope.py` 가 정의한다.

임의 조합을 모두 계산하면 정점 5개일 때 4,095가지가 되어 감당할 수 없다.
업무상 의미 있는 단위만 열거한다.

| 단위 | 대상 컬럼 |
|---|---|
| 문헌1 / 문헌2 / 문헌 전체 | 문헌조사 |
| 현지조사N St.1 … St.5 | 각 정점 (정점 분류군만) |
| 현지조사N 전체 | 해당 회차의 전 정점 |
| 현지조사 전체 | 현지 전 회차 |
| 전체 | 문헌 + 현지 |

정점 분류군 17개 · 나머지 7개 → **총 76개 조합**을 사전 계산한다.

### 단위에 따라 항목 가용성이 바뀐다

데이터가 지지하지 않는 선택은 즉시 드러나야 한다.

| 고른 단위 | 낼 수 없는 항목과 사유 |
|---|---|
| 문헌 단위 | T3 군집지수 — 문헌조사에는 개체수가 없음 |
| 단일 회차·정점 | 조사구분 대조, 회차 비교 — 비교 대상이 단위에 없음 |
| 정점 1개 | 지점별 항목 — 정점을 2개 이상 포함해야 비교 가능 |
| 관속식물 등 | T3 군집지수 — 개체수를 기록하지 않는 분류군 |

낼 수 없는 항목은 숨기지 않고 **사유와 함께** 비활성으로 표시한다.
0으로 채우지 않는다는 원칙과 같다.

## 6. 웹페이지 표출

`TaxonResult` 를 정적 HTML 한 장으로 렌더링한다. 외부 자원을 참조하지 않아
브라우저만 있으면 열린다.

화면은 **분석항목 선택 작업대**다. 결과를 늘어놓는 것이 아니라, 평가서에
넣을 표·그래프를 고르는 도구다.

### 구성
```
좌측 레일  분류군 8개
상단       분석 단위 칩 (문헌 · 정점 · 회차 · 종합으로 묶음)
           분석항목 체크리스트 — 단위에 따라 가용/불가가 바뀜
본문       고른 항목의 표 + SVG 그래프
하단       채택 목록 + 복사용 텍스트
```

### 렌더 서술자
항목마다 전용 JS 를 짜지 않는다. 파이썬(`report_web/payload.py`)이 "이
항목은 이런 형태로 그려라"를 지정하고, 화면은 범용 렌더러만 갖는다.

| 서술자 | 쓰임 |
|---|---|
| `kv` | 항목-값 표 |
| `bars` | 막대 그래프 |
| `stacked` | 조사구분 누적막대 |
| `matrix` | 군집지수·지점별 비교 표 |
| `heatmap` | 지점간 유사도 |
| `chips` | 종 목록 |
| `species` | 종목록 표(단위로 선별) |

그래프는 외부 라이브러리 없이 **인라인 SVG** 로 그린다. 색은 테마 토큰을
쓰므로 라이트·다크 양쪽에서 읽힌다.

### 원칙
- 화면에 뜨는 모든 수치는 분석 계층에서 온다. 렌더링 단계에서 다시
  계산하지 않는다. 종목록 필터링만 출현 비트로 처리하는데, 이는 계산이
  아니라 선별이다.
- 산출 불가 항목은 빈칸이 아니라 **사유 문구**로 표시한다.
- 채택 목록이 이 화면의 산출물이다. 분류군·단위·항목·형태를 표로 뽑아
  평가서 작성 계획에 그대로 쓴다.
- 이 페이지의 수치가 확정되면 그대로 HWPX 로 넘긴다.

# 환경영향평가 생태조사 보고서 자동화 시스템 기획안

## 1. 프로젝트 개요

### 1.1 목적

환경영향평가의 동·식물상 조사 자료를 표준화된 데이터로 관리하고, Python
기반의 결정론적 계산과 로컬 LLM 기반의 문장 생성을 결합하여
한글(HWP/HWPX) 평가서 작성 업무를 자동화한다.

핵심 목표는 단순한 문서 치환이 아니라 다음의 전체 흐름을 하나의 로컬
시스템으로 연결하는 것이다.

**조사 원자료 → 검증·계산 → 표/그래프/사진대지 생성 → 설명 문장 생성 →
HWP/HWPX 보고서 조판**

------------------------------------------------------------------------

## 2. 기본 설계 원칙

### 2.1 역할 분리

시스템은 각 구성요소의 책임을 명확히 분리한다.

  구성요소               주요 역할
  ---------------------- ----------------------------------------------
  Excel                  동·식물상 원자료 입력 및 관리
  Python                 데이터 검증, 집계, 통계 계산, 표·그래프 생성
  Local LLM              계산된 사실을 기반으로 보고서 문장 작성·수정
  pyhwpx / 한글 자동화   표, 문장, 이미지 등을 실제 한글 문서에 배치
  HWP/HWPX 템플릿        최종 평가서의 서식과 조판 규칙 유지

**원칙:** LLM에게 계산을 맡기지 않는다. 수치와 목록은 Python이 확정하고,
LLM은 확정된 결과를 자연어로 표현한다.

## 3. 원자료 구조

### 3.1 Excel 중심 데이터 관리

사용자는 분류군별 시트에서 문헌조사 및 현지조사 결과를 체크하거나
입력한다.

예상 분류군은 다음과 같다.

-   식물상
-   포유류
-   조류
-   양서·파충류
-   육상곤충류
-   어류
-   저서성대형무척추동물
-   기타 사업별 조사대상 분류군

각 시트는 가능한 한 동일한 데이터 원칙을 유지하며, 향후 분석을 고려하여
Long Data 구조를 우선한다.

### 3.2 주요 필드 예시

-   분류군
-   과명
-   국명
-   학명
-   조사구분(문헌/현지)
-   조사차수
-   조사일자
-   조사지점
-   출현 여부
-   개체수 또는 관찰량
-   법정보호종 여부
-   비고

필드 구성은 실제 환경영향평가 양식과 조사 방법에 맞추어 추후 확정한다.

## 4. Python 데이터 처리 엔진

Python은 시스템의 계산 및 검증 계층으로 사용한다.

### 4.1 기본 처리

-   체크된 출현종 추출
-   분류군별 종목록 생성
-   조사차수별 출현종 산출
-   전체 출현종수 계산
-   중복 종 제거
-   문헌조사와 현지조사 비교
-   법정보호종 추출
-   지점별·시기별 집계

### 4.2 생태통계

필요한 경우 Python에서 직접 계산한다.

-   종수
-   개체수
-   우점도
-   종다양도
-   균등도
-   풍부도
-   조사시기별 변화
-   조사지점별 비교

모든 계산 결과는 LLM에 전달하기 전에 Python에서 확정한다.

### 4.3 그래프 생성

계산된 결과를 이용하여 평가서용 그래프를 자동 생성한다.

예:

-   조사시기별 종수
-   분류군별 출현종수
-   지점별 다양도
-   조사차수별 변화
-   기타 사업별 요구 그래프

그래프 파일명과 보고서 내 삽입 위치를 연결할 수 있도록 규칙화한다.

## 5. Local LLM 계층

### 5.1 목적

인터넷이나 외부 API에 평가서 데이터를 전송하지 않고 로컬 PC에서 보고서
문장을 생성한다.

후보 모델:

-   Gemma 계열
-   Qwen 계열
-   Llama 계열

초기에는 Ollama 등의 로컬 런타임을 이용하여 모델 교체가 쉬운 구조로
구현한다.

### 5.2 LLM 입력

LLM에 Excel 원본 전체를 무분별하게 전달하지 않는다.

Python이 다음과 같은 구조화 결과를 생성한 뒤 LLM에 전달한다.

``` json
{
  "taxon": "조류",
  "survey_round": 2,
  "species_count": 35,
  "protected_species_count": 2,
  "dominant_species": ["종A", "종B"],
  "diversity_index": 2.81
}
```

### 5.3 LLM 역할

-   조사결과 설명 문장 생성
-   기존 평가서 문체에 맞춘 문장 수정
-   표와 그래프에 대한 설명
-   조사차수 간 변화 서술
-   정해진 사실을 보고서 형식의 자연어로 변환

### 5.4 LLM이 담당하지 않는 영역

-   종수 직접 계산
-   다양도 지수 직접 계산
-   법정보호종 판정의 최종 결정
-   임의의 종 추가 또는 삭제
-   표의 실제 조판
-   페이지 분할 판단의 최종 실행

## 6. 종목록 자동 생성

종목록은 시스템의 핵심 산출물 중 하나이다.

### 6.1 처리 흐름

**Excel 체크 → Python 필터링 → 종목록 생성 → 페이지 단위 분할 → HWP/HWPX
삽입**

### 6.2 한글 문서의 특성 반영

환경영향평가서의 긴 종목록은 단순히 하나의 긴 표로 처리하기보다 실제
평가서 조판 관행에 맞추어 페이지 단위로 관리할 필요가 있다.

자동화 모듈에서 다음을 처리한다.

-   페이지당 적정 행 수 계산 또는 규칙 적용
-   표 자동 분할
-   다음 페이지에서 표 머리글 반복
-   페이지별 표 크기 유지
-   마지막 페이지 처리
-   표 테두리와 셀 속성 통일
-   필요 시 분류군별 서로 다른 표 양식 적용

즉, **종목록 데이터와 페이지 조판 로직을 분리**한다.

## 7. 사진대지 자동화

### 7.1 사진 입력 구조

사용자가 정해진 폴더에 보고서에 사용할 사진을 넣는다.

예:

``` text
photos/
├── plants/
├── mammals/
├── birds/
├── herpetofauna/
├── insects/
└── survey_sites/
```

### 7.2 기본 처리

Python이 폴더를 탐색하여 이미지 수를 확인하고 사진대지를 생성한다.

예상 기능:

-   사진 수 자동 인식
-   2×3, 3×3, 4×4 등 적절한 배열 선택
-   표 셀 생성
-   셀 크기에 맞춘 이미지 삽입
-   이미지 비율 유지
-   사진 아래 셀에 캡션 입력
-   페이지 초과 시 다음 사진대지 자동 생성

### 7.3 캡션

초기 단계에서는 **이미지 파일명을 그대로 캡션으로 사용**한다.

예:

``` text
붉은머리오목눈이.jpg
```

→ 사진 아래 셀:

``` text
붉은머리오목눈이
```

향후에는 Excel의 사진 메타데이터나 LLM을 이용하여 캡션을 보정할 수 있다.

## 8. HWP/HWPX 자동화

### 8.1 pyhwpx의 역할

pyhwpx 및 한글 자동화 인터페이스는 최종 문서를 실제로 조작하는 실행
계층으로 사용한다.

주요 대상:

-   기존 평가서 파일 열기
-   지정 위치 탐색
-   기존 문장 교체
-   표 생성
-   행·열 추가 및 삭제
-   셀 병합
-   셀 크기 설정
-   글꼴 및 문단 설정
-   테두리 설정
-   이미지 삽입
-   사진대지 생성
-   표 페이지 분할
-   최종 파일 저장

### 8.2 서식 자동화 원칙

LLM이 테두리 두께나 셀 여백 같은 세부 서식을 직접 결정하지 않는다.

대신 표 스타일을 사전에 정의한다.

예:

``` text
TABLE_SPECIES_LIST
TABLE_SURVEY_RESULT
TABLE_PHOTO_PLATE
TABLE_PROTECTED_SPECIES
```

각 스타일에 다음 속성을 코드 또는 템플릿으로 정의한다.

-   선 종류
-   선 두께
-   글꼴
-   글자 크기
-   정렬
-   셀 여백
-   행 높이
-   열 너비
-   제목 행 형태

가능하면 기존 평가서의 정상적인 표를 템플릿 객체로 활용하여 복제한 뒤
내용과 구조를 변경하는 방식도 검토한다.

## 9. 보고서 템플릿 식별 방식

기존 평가서에서 자동으로 수정할 영역을 명확하게 식별할 필요가 있다.

예:

``` text
{{BIRD_SPECIES_TABLE}}
{{BIRD_RESULT_TEXT}}
{{BIRD_DIVERSITY_GRAPH}}
{{BIRD_PHOTO_PLATE}}
```

또는 문서 내부의 별도 식별자, 누름틀, 필드명 등 한글 자동화에 적합한
방식을 시험하여 최종 선정한다.

핵심은 AI가 문서 전체를 해석하여 위치를 추측하는 것이 아니라,
**프로그램이 수정할 위치를 결정론적으로 찾을 수 있도록 하는 것**이다.

## 10. 전체 처리 파이프라인

``` text

   ↓

   ↓

   ↓
표 / 그래프 / 문장 / 사진대지 삽입
   ↓
[최종 환경영향평가서]
```

## 13. 시스템의 핵심 철학

이 시스템에서 AI는 중심 데이터 처리 엔진이 아니다.

**환경영향평가 업무 규칙과 생태조사 데이터 구조가 시스템의 중심이며,
AI는 그 결과를 사람이 작성한 보고서처럼 표현하는 언어 계층이다.**

따라서 시스템은 다음 구조를 유지한다.

> **Excel은 원자료, Python은 계산, Local LLM은 문장, pyhwpx는 한글 문서
> 조판을 담당한다.**

이를 통해 LLM 모델이 향후 변경되더라도 데이터 처리 및 보고서 자동화
시스템 전체를 다시 만들 필요가 없는 구조를 지향한다.

## 14. 1차 구현 범위

초기 테스트에서는 전체 환경영향평가서를 한 번에 자동화하지 않는다.

첫 번째 프로토타입은 하나의 분류군을 대상으로 다음 흐름을 끝까지
구현하는 것을 목표로 한다.

``` text
Excel 종목록
→ 출현종 체크
→ Python 종수 계산
→ 종목록 표 생성
→ 간단한 그래프 생성
→ Local LLM 결과 문장 생성
→ 기존 HWP/HWPX 평가서의 지정 위치에 자동 삽입
→ 결과 파일 저장
```

이 단일 파이프라인이 안정적으로 동작한 이후 사진대지, 다른 분류군,
복잡한 통계 및 전체 평가서 자동화로 확장한다.

## 15. 장기 확장 방향

향후 다음 기능으로 확장할 수 있다.

-   전체 동·식물상 분류군 통합
-   법정보호종 자동 검토
-   과거 조사자료와 비교
-   조사차수별 자동 서술
-   보고서 품질 검증
-   표와 본문 수치 불일치 자동 탐지
-   종명 오탈자 및 학명 검증
-   사진 파일과 종목록 연결
-   GIS 조사자료 연계
-   사업별 평가서 템플릿 관리
-   회사별 보고서 양식 관리
-   로컬 RAG를 이용한 기존 평가서 문체 및 작성 규칙 참조

# 작업 인수인계 — EIA_report

새 대화에서 이어받을 때 이 문서를 먼저 읽는다. 무엇이 왜 그렇게 되어
있는지, 지금 어디까지 왔고 다음이 무엇인지를 담았다.

**최종 상태**: 분석 계층 완료 · 좌우 분할 웹 작업대 완료 · HWPX 조판 미구현
**기본 브랜치**: `main` (작업 브랜치와 동기화됨)

---

## 1. 이 프로젝트가 하는 일

환경영향평가 **동·식물상** 조사자료를 표준화해 관리하고, 분석 결과를 보며
평가서에 넣을 표·그래프를 결정한 뒤, 최종적으로 한글(HWPX) 평가서 작성을
자동화한다.

### 지켜 온 원칙 (바꾸지 말 것)

| 원칙 | 뜻 |
|---|---|
| 계산은 Python, 표현은 화면 | 화면은 사전 계산된 값을 **고르고 그릴 뿐** 지수를 계산하지 않는다 |
| 산출 불가는 사유와 함께 | 낼 수 없는 항목을 0으로 채우지 않는다. 왜 못 내는지 보여준다 |
| 없는 정보를 지어내지 않는다 | 국명 결측 1,061건은 표기만 통일하고 그대로 뒀다 |
| 양식은 문서에서 읽는다 | 스타일 ID·장 번호를 고정하지 않는다. 업체·사업마다 다르다 |

## 3. 지금까지 한 일

### 3.1 원자료 정비 (v6 → v7, `tools/repair_datamaster.py`)

변경 1,195건. 마스터DB 의 `정비이력` 시트에 전부 남아 있다.

- 계급 보정 680건 — 연결어 없는 3단어 학명을 종 → 아종
- 중복 병합 370건 — 관속식물 404행 감소 (6,058 → 5,654)
- 국명 표기 통일 1,059건 — `국명없음`·`국명미정` 세 갈래를 `[국명없음]` 으로
- 학명을 ASCII 로 통일 (유니코드 이탤릭은 정렬·검색을 깨뜨린다)
- `dual_habitat_ref_id` 교차 참조 복구 (수서곤충 1,516쌍)

**지어내지 않은 것** — 국명 결측 1,061건, 이명 18그룹, 잡종 계급 82건은
분류학적 판단이 필요해 그대로 뒀다.

### 3.2 정점조사 도입 (v7 → v8, `tools/make_station_sample.py`)

어류·저서성대형무척추동물은 정점조사를 한다.

```
현지조사1 → 현지조사1_St1 … 현지조사1_St5
```

시드 고정이라 언제 돌려도 같은 결과다. 개체수는 새로 생성했으므로 이 두
분류군의 v7 이전 수치는 더 이상 유효하지 않다.

### 3.3 분석 계층

| 모듈 | 역할 |
|---|---|
| `data/schema.py` | 분류군 사양·컬럼 구성. 컬럼은 상수가 아니라 함수로 만든다 |
| `data/loader.py` | `species_id` 조인, 분류군별 값 파싱 |
| `analysis/scope.py` | **분석 단위** — 회차·정점 조합 76개 |
| `analysis/stations.py` | 지점별 집계·Sørensen 유사도 |
| `analysis/item_catalog.py` | 항목 26개 × 단위별 표·그래프 산출 가능성 판정 |
| `analysis/runner.py` | 단위별 분석 실행·집약 |

**분석 단위가 이 시스템의 핵심 개념이다.** 임의 조합을 다 계산하면 정점
5개일 때 4,095가지가 되므로 업무상 의미 있는 단위만 열거한다. 단위에 따라
항목 가용성이 바뀐다 — 문헌 단위는 개체수가 없어 군집지수를 못 낸다.

### 3.4 HWPX 템플릿 추출 (`hwpx/template.py`)

기존 평가서에서 목차와 표·그림 자리를 뽑는다. **한글 프로그램이 필요 없다.**

- 스타일 ID 를 쓰지 않는다. 문서마다 값이 달라 이식되지 않는다.
  번호 체계(`1)` · `(1)` · `①`)와 캡션 표기를 1차 신호로 쓴다.
- `renumber(chapter)` — 장 번호를 다시 매긴다. 동·식물상은 사업마다
  7.1.1 · 8.1.1 · 9.1.1 로 달라지며 다른 평가 매체와 조율해야 한다.

샘플 추출 결과 — 목차 45개, 표 16개, 그림·사진 14개.
실제 결함도 잡았다: 9.1.1 문서에 섞인 `사진 8.1.1-1`.

### 3.5 웹 작업대 (`report_web/`)

**좌우 분할 화면.** 좌측은 분석, 우측은 보고서 미리보기.

```
[분류군 레일] │ [분석: 단위·항목 선택 → 결과·그래프] │ [보고서 미리보기: 목차·자리 배정]
```

- 좌측에서 항목을 "평가서 반영" 체크 → 우측 "배정 대기" 로
- 우측 목차의 표·그림 자리에 드롭다운으로 배정 → 진행도 갱신
- 작성 계획을 탭 구분 텍스트로 복사

렌더링은 **서술자 방식**이다. 항목마다 전용 JS 를 짜지 않고 파이썬이
`kv`·`bars`·`stacked`·`matrix`·`heatmap`·`chips`·`species` 중 하나를
지정하면 화면은 범용 렌더러로 그린다. 그래프는 외부 라이브러리 없이
인라인 SVG 다.

## 4. 실행

**모든 명령은 `eia-report-automation/` 안에서.**

```bash
python -m src.analyze_web                 # 분석 → output/analysis_report.html
python -m src.analyze_web --chapter 7.1.1 # 장 번호 조율해서 생성
pytest -q                                 # 테스트 121개
```

Windows 는 `run.bat` 더블클릭. 아나콘다도 자동 탐색한다(PATH·CONDA_PREFIX·
설치 경로·레지스트리 5단계).

원자료 재생성은 평소 필요 없다.

```bash
python -m tools.repair_datamaster     # v6 → v7
python -m tools.make_station_sample   # v7 → v8
```

## 5. 다음에 할 일

사용자와 합의된 방향이다. **분석 방법론은 차후 결정**하기로 했고, 실행은
시각화를 보며 단계별 지시에 따른다.

### 5.1 구조적으로 비어 있는 것 (우선순위 순)

현재 코드를 점검해 확인한 격차다. 세부 분석방법과 표·그래프 표출은
**사용자가 웹페이지를 운영하며 직접 검증·수정을 지시**하므로, 아래는
그 지시를 받기 전까지 손대지 않는다.

1. **종 매칭** — 가장 큰 결함이며 지시와 무관하게 실재한다. 지금은
   `species_id` 조인뿐인데 **실제 조사자료에는 species_id 가 없다.**
   조사원이 학명·국명만 적어 오면 마스터DB 와 연결할 방법이 없다.
   파일럿이 가상데이터(이미 id 보유)라 드러나지 않았을 뿐이다.
   학명·국명 정확 매칭 후 유사도 매칭, 매칭 유형과 신뢰도를 함께 돌려
   사람이 검수할 수 있어야 한다.
2. **학명 서식 파싱** — 지금은 학명 전체를 이탤릭 처리한다. 명명자·계급
   약어는 정자체여야 맞다. HWPX 용과 웹용을 **한 로직에서 파생**시켜야
   두 곳이 갈라지지 않는다. 나중에 붙이면 늦다.
3. **위계 종목록** — 지금은 과·학명 순 평면 정렬. 평가서는 문→강→목→과
   헤더 행이 들어간 트리여야 한다.
4. **서술문 생성** — 기획은 이 자리에 LLM 을 뒀으나, "총 O목 O과 O종이
   확인되었다" 같은 정형 문장은 결정론적으로 만드는 편이 재현성·검수성
   면에서 낫다. LLM 은 정형화되지 않는 서술에만 쓴다.
5. **비율 보정** — 반올림으로 비율 합이 100% 를 벗어나는 문제.
6. **자리별 처리 상태** — 자동 채움 / 수동 필요 / 서술 채움 / 원본 유지.
   우측 패널이 자리마다 표시할 상태값이며, 지금은 채움 여부만 있다.

### 5.2 확인이 필요한 미결 사항

| 항목 | 상태 |
|---|---|
| 귀화식물 기준종수 | 현재 `taxon_specific.NATURALIZED_TOTAL_KR = 375`. 참조 문헌마다 다르므로 사용자가 쓰는 값으로 확정해야 한다. 산출 결과에 사용한 분모를 함께 표기하고 있다 |
| 분류군별 집계표 형식 | 현재는 과별 집계. 평가서가 문(門) 단위 고정 행을 요구하면 별도 항목이 필요하다 |
| 조사일자 | 전 분류군 없음. 계절별 분석이 막혀 있다 |
| 육상 분류군 정점 | 정점보다 조사구역·노선 개념이 맞을 수 있어 조사 설계와 함께 정해야 함 |

### 5.3 HWPX 미리보기 전략 (검토 완료)

`rhwp`(Rust+WASM HWP 뷰어)를 우측 패널 주력으로 쓰는 안을 검토했으나
**지금은 이르다**고 판단했다.

- v0.5~0.8 "scaffolding", 개발자 본인이 프로덕션 비권장
- **이미지 미지원** — 사진대지·그래프가 정확히 안 그려진다
- 90% 맞는 미리보기는 없느니만 못하다. 검토자가 믿고 넘어간다

채택한 방향: 1단계는 **구조 미리보기**(현재 구현), 진짜 지면이 필요하면
로컬 한글이 뽑은 PDF 를 띄운다(2단계). rhwp 는 v1.0 이후 재평가.

## 6. 작업 방식 (변경됨)

**로컬에서 작업하고 저장소로 푸시한다.** 이전처럼 저장소에서 작업한 뒤
로컬로 클론하지 않는다.

```bash
# 시작할 때
git pull origin main

# 작업 후
git add -A
git commit -m "..."
git push origin main
```

충돌을 줄이려면 작업 시작 전 `git pull` 을 습관으로 둔다.

### 표·그래프 표출은 운영하며 정한다

세부 분석방법과 표·그래프 표출 방식은 **사용자가 웹페이지를 직접 운영하며
검증하고 수정을 지시**한다. 지시 없이 표출 형식을 바꾸지 않는다.

과거 시스템(`EAI_flora_local`)은 **더 이상 참고하지 않는다.**
`doc/EIA_report_algorithm_summary.md` 는 이력용으로만 남겨 둔 것이며
설계 근거로 쓰지 않는다.

### 원격 세션의 한계 (기억할 것)

사용자 로컬 PC 경로에 접근할 수 없다. 필요한 파일은 저장소를 통해 주고받는다.
